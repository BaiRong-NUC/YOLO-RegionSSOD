## 2. 现有基础与尚缺证据

当前 `80e9f2b` 已完成固定 split seed0、固定 B1 教师、学生 seed0/1 的独立 30 epoch B2/P1 对照。
P1−B2 的 mAP50-95 平均配对差为 +0.2893±0.0644 pp，small recall 为 +1.7854±0.1304 pp，
两者方向保持；large recall 方向不同。另有尺度阈值复验、no-ignore 对照与四类诊断案例。
当前原 Gate 3 未达到，不改变该历史判定；没有以此证明跨 split 泛化、官方 AP_small 或统计显著性。

这些成果构成第一篇的基础，不能仅按“尺度阈值、软权重、ignore”拆成三篇投稿。
B0、正式 100 epoch B2/P1、其他面积预算及独立 split/教师尚未完成，须按第一篇的问题确定必要补充规模。
S³OD 已包含尺度阈值和教师负样本处理；创新论证必须继续使用现有逐项对照，不能以“换成 YOLO”或
“首次把已有模块组合”作为主要贡献。若低成本验证没有支持新机制，保留诊断性结论，不强行堆叠模块。

## 3. 三篇文章的独立问题和证据

### A：局部标注下的小目标半监督检测——第一优先

暂定题目：**面向区域局部标注的尺度可靠性航拍小目标半监督检测方法**。
沿用现有 RegionSSOD，回答“有限标注区域之外存在真实目标时，如何降低伪标签缺失造成的监督污染”。

- 核心内容：区域面积预算协议、可靠的尺度伪标签策略及未知区域处理，明确真正有实验支持的机制。
- 现有基础：B1/B2/P1 seed0 主表、B2/P1 两学生 seed、尺度消融复验及案例；软权重尚无全量独立正向证据。
- 先补低成本漏检归因，区分教师无候选、阈值过滤、类别/定位错误及 NMS 抑制，决定是否需要替换一个机制。
- 投稿前证据目标：正式公平训练对照、多个面积预算中的必要点、完整单因素消融、重复随机性验证、
  至少一个相关 SSOD 方法或最接近机制的同协议对照；外部数据只在类别映射/标注协议审计后使用。
- 既有的同 split/教师两学生 seed 不能同时算作独立 split/独立教师重复。新 split 要重新建立对应教师和伪标签。
- 验收以完整原图验证、可追踪权重/日志、原始精度统计为准；不将 5 epoch 筛选包装成最终证据。

停止点：科学问题和独立贡献没有建立时，先完成诊断与写作，不立即扩大到全部模型、预算和数据集。

### B：漏检感知的伪标签补全——第三顺位、独立新增研究

暂定题目：**面向航拍小目标的漏检感知伪标签补全与可靠自训练方法**。
回答“教师没有提供足够小目标监督时，如何增加可信目标，同时抑制错误自强化”。

- 候选主机制：跨尺度/多视图一致性支持的伪标签补全与接受/unknown 判定。一次只选择一个主机制。
- 先分析相同训练输入上的教师候选，不用验证 GT 或隐藏训练 GT 生成训练伪标签；隐藏 GT 仅作离线质量诊断。
- DINOv3 可以作为冻结特征教师候选；LoRA 仅在确有域适配需要时作为工具。不是同时加入两者的预设要求。
- CLIP 只有在能明确解决类别语义混淆时再进入候选；当前固定类别定位任务不以“接入大模型”代替问题论证。
- 核心对照：固定教师单轮、普通第二轮自训练、采用相同更强教师/相同额外预测预算的普通补标签，
  以及本方法；不能把更大教师或额外数据的收益直接归于补全规则。
- 证据：新增伪框数量/分尺寸 precision-recall、错误累积、不同更新轮数、学生完整验证结果，另记教师及重生成开销。
- 若不同教师用了额外标注或外部数据，单列其成本与训练信息，不与原“10% 面积预算”无注释合并。

与 A 的界限：A 的固定离线策略作为已公开/待投稿基线并明确引用；B 的新问题是缺失候选的发现与更新可靠性，
不能只把 A 换一个阈值或换教师后重复写作。B 没有独立增量时，合入学位论文分析，不强行形成第三篇。

### C：小目标召回约束的压缩与树莓派部署——第二优先、毕业必做

暂定题目：**面向树莓派边缘部署的航拍小目标检测蒸馏与结构化压缩方法**。
回答“在明确的边缘计算预算下，怎样尽量保留小目标检出能力”。

建议流程：验证过的教师 → 蒸馏训练学生 → 结构化剪枝 → 教师辅助恢复微调 → 后端支持时再量化 → 树莓派完整测试。
此流程是候选工作路线，蒸馏/剪枝顺序本身不是新贡献。可研究的独立技术问题是小目标敏感通道/特征的保留、
可靠区域的蒸馏约束或召回与端侧时延的联合选择；先选一个有依据的主机制。

**硬件支持必须先验证，再决定剪枝结构。** 自定义通道/算子若无法由最终编译器或后端执行，不推进到长程训练。

最小有辨识力的对照：

| 模型 | 用途 |
|---|---|
| 未压缩 YOLO11s/P1 | 精度与端侧开销参照 |
| 直接训练的 YOLO11n 等原生小模型 | 排除“只需换小模型”的替代解释 |
| 仅蒸馏的小学生 | 判断知识迁移作用 |
| 结构化剪枝 + 普通恢复训练 | 压缩对照 |
| 相同结构/恢复预算的蒸馏剪枝方法 | 判断提出策略是否优于普通恢复 |
| 上述可部署模型的量化版本（可选） | 单独检查量化损失及实际速度，不假定必有加速 |

使用相同数据、监督预算和评估口径；较大教师另列成本。只将权重置零而未移除结构，不据此声称树莓派加速。
压缩与恢复使用局部标注任务时，蒸馏也须尊重 unknown 区域，不能将其统一当确定背景。

## 4. 树莓派部署协议与验收

### 4.1 当前假设与先行验证

硬件尚未确认，暂以 **Raspberry Pi 5、8 GB、纯 CPU、64 位系统、单张图像检测**规划；这是排期假设，
不是已购买硬件或已测性能。原课题继续使用图像检测，不自动扩展成视频时序任务。

- 第一个里程碑：原生小模型和未剪枝模型能完整导出并在板上执行，比较结果与原模型是否一致。
- 纯 CPU 路线先比较 NCNN 与 ONNX Runtime 等实际可用后端，固定本机版本；NCNN 只是优先验证候选。
- 训练仍保留已验收 yolo 环境；导出/端侧依赖单独记录，不能为部署覆盖当前冻结训练环境。
- 若允许 AI HAT，另建带加速器路线，先确认模型/算子及剪枝后拓扑能编译和量化。
  NPU 结果与纯 CPU 结果分表，不把加速卡带来的速度全部归于剪枝。
- 教师、大型视觉基础模型和 LoRA 适配可以留在工作站，最终树莓派只部署确定的学生推理链。

官方 Raspberry Pi AI HAT 提供的是受支持模型的 Hailo 加速；普通 ONNX 导出不等于获得 NPU 可执行产物。
硬件和精度/速度最低要求明确后，再确定唯一主后端与模型结构，不先承诺 960 输入实时运行。

### 4.2 必须报告的准确率与完整链路

| 项目 | 记录方式 |
|---|---|
| 精度 | 完整 548 图 mAP50、mAP50-95、small/medium/large 固定操作点 recall，导出前后分别评估 |
| 输入 | 原图尺寸、模型输入与缩放/切片规则；640 和 960 分开报告，改分辨率的影响与压缩影响分开 |
| 模型体积 | 参数量、模型文件大小、MACs/FLOPs 的计算约定和输入形状 |
| 速度 | batch1 推理时间和完整端到端延迟分别报告；包含解码、缩放、切片、模型、NMS、结果合并 |
| 统计 | 固定预热、重复次数/图像清单、线程数、延迟中位数与 P95；不只报最好一次 |
| 资源 | 进程峰值内存、CPU 使用、板卡型号/内存、系统/后端版本、电源/散热配置 |
| 持续运行 | 持续负载至少 20 分钟，记录温度、降频与延迟变化；功耗有测量设备才报告 |
| 可复现 | 学生 checkpoint 与导出模型哈希、配置、量化校准清单、测量脚本及原始 CSV/日志 |

量化校准使用训练数据，不能使用验证或测试标签。导出/量化后重新核对实际可执行模型的检测结果；
不能用 PyTorch 或桌面 GPU 上的精度/速度代替 ARM 板端结果。使用切片时，速度按完整原图计算，不能只报单 tile。

### 4.3 暂定工程筛选目标

在硬件/截止日期尚未确定前，下面只作为待讨论的早期目标，不是已实现指标、学校要求或期刊录用阈值：

- 同输入与同后端，相对未压缩学生的端到端延迟降低至少约 30%；实际 CPU 基线测量后可调整目标。
- 相对同输入的未压缩模型，mAP50-95 损失控制在约 1 pp 内，small recall 损失约 1.5 pp 内；
  同时与直接训练原生小模型比较，不能只选有利参照。
- 若延迟没有降低或小目标损失明显超出预算，回退剪枝率或方法，不用缩小输入掩盖压缩损失。
- 绝对 FPS/每张耗时待板端基线和用户需求确定，不能直接承诺 30 FPS。

## 6. 专利替代路线及公开顺序

“申请通过”目前没有足以确定学校节点的材料，暂不计作“只提交即可”或“必须授权”。
需要确认发明/实用新型类型、受理文件/其他审查结果、发明人和申请人要求，再核定这条毕业路线。

两项候选交底方向为：

1. 局部标注下的一致性约束伪标签补全与未知区域处理方法。
2. 面向边缘设备的小目标召回约束压缩与完整图像推理方法。

只有形成可区分且具备技术依据的方案，才进入查新和交底。不能把同一方案改名拆成两件，也不把
“采用 LoRA / 蒸馏 / 剪枝 / 树莓派”这些已有技术名词直接当成可专利的新方案。

申请前由导师/学校知识产权部门核对既有论文、预印本、答辩公开材料和 Gitee 仓库是否公开。
若方案尚未公开且考虑专利，优先安排申请文件，再安排论文/代码公开；已公开的内容需单独评估。
该安排依据专利法对新颖性和申请日前公开技术的要求，不将论文录用、专利受理与专利授权混为一谈。

## 7. 相对研发排期与交付门槛

毕业截止日期未知，下列为约 20 周的研发示例，需结合学校节点、硬件和计算资源重排；
**不包含不可控的审稿/返修等待，不承诺 20 周内取得三篇录用**。论文 A 的审稿与后续研发并行，
同一稿件按目标期刊规则单投。

| 阶段 | 工作 | 明确交付/继续条件 |
|---|---|---|
| 第 1 周 | 核实毕业口径、硬件与期限；整理 A 缺口；做树莓派原生模型导出/执行可行性验证 | 学校要求清单、板端基线与唯一主后端候选；无硬件时只完成桌面导出，不能算上板验收 |
| 第 2–6 周 | 优先 A 的必要正式对照与写作；必要时做专利查新/交底 | 足以支撑独立方法结论的实验与完整稿件；未形成贡献则回到单机制诊断 |
| 第 7–12 周 | 优先 C：小学生/蒸馏/剪枝小矩阵，恢复训练与上板实测 | 导出可执行、完整精度/端到端时延/内存/热稳定性表及第二份候选稿件 |
| 第 13–20 周 | 有余量时推进 B，和 A/C 审稿返修、学位论文写作并行 | 可靠补全有独立增量才形成第三篇，否则作为学位论文分析 |
| 全过程 | 学位论文和证据同步维护 | 每阶段同步实验图表、日志、引用和与前文关系，不等三篇结束才写大论文 |

按用户2026-10-30最新要求，至少完整30epoch才判断候选性能；
短程只能检查工程故障，不能按5epoch结果淘汰机制。Codex先记录固定预算、
比较对象、停止条件和命令，当前自主单候选固定30epoch；
“30次”按epoch理解，不启动30组独立训练。
实际启动时创建临时进度定时任务，只在完成、失败或需处理时通知，结束后清理。
用户补充授权：训练期间可选择暂停持续目标等待，或利用等待时间核对相关论文；
训练进程和临时监控继续运行，训练结束后触发验收并接续已授权目标。
运行期不通过持续目标高频重复轮询；不改本轮冻结源码或并行新候选。
若可用控制无法将目标状态恢复为active，应明确通知用户需要点击继续，
不能虚报已恢复或新建目标绕过。
值得扩大训练时，先完成可复核的配置、预检与验收代码，再给用户训练指令，由用户运行
更长训练/更大矩阵；不自动启动100epoch、多个新split或更大教师。
每轮代码和文档修改使用中文提交Git，并按本次新增授权push；不购买硬件或提交专利。
原 Gate 3 结论保留，后续路线采用单独的研究假设和预先记录的指标，不回写旧结果。

## 8. 投稿候选和尚未锁定事项

候选池可先考虑《计算机工程与应用》《计算机应用研究》《计算机工程与设计》等计算机类期刊。
