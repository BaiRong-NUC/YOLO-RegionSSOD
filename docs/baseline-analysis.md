# 第二步 · 按功能拆解基线

**状态：待执行。** 第一步已经测到整图和切片的小目标 AP 差异。这一步要回答：同一张航拍图里，切片救回的小目标，整图推理最早在哪个可观察环节丢掉了它？如果大部分目标在去重前已有位置准确、分数可用的框，就应优先查后处理。若有些目标在放大后才出现合格候选，再查输入尺度和检测头。[第一步证据](reproduce/README.md)

## 固定诊断起点

- **框型与范围**　VisDrone2019-DET 十类水平框，以原图上 COCO small 范围内的标注为主。行人和车都可入组，记录类别与尺寸。沿用现有忽略区、截断和类别过滤口径。
- **诊断基线**　YOLO11s Detect，Ultralytics 8.4.172。两份历史裁片训练权重分别独立配对。整图每次前向 `640×640`、FP32、`rect=False`，置信度门槛 0.001、视图内 NMS IoU 0.7、每图最多 500 框。权重路径、哈希、运行命令见 [SAHI 复现卡](reproduce/sahi/README.md)。
- **三个独立对照**　主线用同一权重比较整图与 SAHI 整图加切片。查尺度筛框时，两臂使用相同三尺度候选。查重叠降分时，两臂共享同一组解码候选。每次只切换对应论文的一个开关。[切片入口](../scripts/reproduce/sahi/evaluate_visdrone.py) · [尺度筛框](../scripts/reproduce/snip/evaluate.py) · [重叠降分](../scripts/reproduce/softnms/evaluate.py)

## 先用一张真图走通，再看整组目标

1. 在 val 全部 548 张图按原入口运行基线和切片。用同类别、原图坐标、IoU 0.50 的 COCO 一对一匹配标记每个有效小目标。分别保留**两臂都检出、只被切片检出、只被整图检出、两臂都漏掉**四组。这个工作点用于追踪单个目标，总体精度仍按 IoU 0.50～0.95 计算。
2. 先用种子 0，按文件名选第一张同时含“切片救回”和“两臂都检出”目标的图。记录文件名、标注 ID、类别、原图框；在种子 1 上追同一张图和同一批目标。若没有满足条件的同图样本，各组选排序最前的图并记录。示例用来解释过程，比例用全组计算。
3. 为每个目标保留一个可回溯的候选编号，串起来源视图、检测层与网格位置、分数、框、阈值筛选、视图内去重、跨视图合并及最终匹配。邻近标注竞争同一个框时记录双方，避免把一个预测算作救回两个目标。

## 沿输入追到评测

下表是执行时要查的位置。`80×80 / 40×40 / 20×20` 是 640 输入按步长 8/16/32 的预期网格。实际层号、输入输出 `B×C×H×W`、类别数及候选数从加载的权重和本次前向读取，随样本记录。

| 环节与源码定位 | 接收 → 输出，以及承担的能力 | 哪组样本值得查；同时排查什么 |
|---|---|---|
| 预处理：`read_validation`、`prepare_image`、`LetterBox` | 原图和原图框 → 网络张量与映射后的框。记录缩放、填充、裁片偏移和目标在输入上实际占的像素。 | 对比切片救回与同图都检出的小目标。若两组缩小后尺寸相近，再查遮挡、上下文和裁片边缘。 |
| 骨干：加载模型的 `model.model`，按 YOLO11 配置的 `backbone` 顺序 | 输入张量 → 多步长特征。记各出口层号、通道、空间尺寸和标注覆盖的网格范围。 | 查缩放后只占极少网格且无合格候选的目标。微弱激活本身不足以定位原因，还要核对后续融合与预测。 |
| 特征融合：配置 `head` 内上采样、`Concat` 与下采样路径 | 各级骨干特征 → 送入 `Detect` 的三层特征。记录每路来源层号及形状。 | 比对同类、相近像素尺寸的成功与失败目标，查哪一尺度产出的候选更接近标注；切片同时改变背景范围。 |
| 预测头与解码：`Detect.forward`、`Detect.decode_bboxes` | 三层特征 → 各网格分类与回归输出 → 各类别分数和输入坐标框。回映原图，记录阈值前同类候选的最佳 IoU 及其分数，也查错类高分框。 | 好位置但低分提示查分类；高分但位置偏提示查回归。先用标注框做坐标往返核对，排除缩放或偏移误差。 |
| 分配与损失（训练支路）：`TaskAlignedAssigner`、`v8DetectionLoss` | 训练标注、锚点及预测 → 正样本掩码、目标分数、分类与框回归损失。若候选在去重前持续缺失，再从训练集取相同类别、尺寸的真实目标，按层统计正样本数及定位误差。 | 将同组成功例和失败例的训练侧相似样本对照。分配少可能来自当前预测质量；验证图上的漏检本身无法证明训练分配不足。 |
| 后处理：`CandidatePredictor.postprocess`、SAHI `get_sliced_prediction` | 解码框 → 阈值筛选 → 视图内去重 → 映回原图及跨视图合并。记录被谁压掉、两框 IoU、降分前后排序及 500 框截断。 | 查拥挤同类中去重前已有合格框的目标；用同一目标的重复框作对照，区分救回邻居与多报一次。 |
| 评测：`evaluate`、`COCOeval` | 原图预测和有效标注 → 逐目标匹配、AP_small 和总体 AP。核查类别、忽略标志和同一标注的竞争框。 | 查诊断中“有框”却未匹配的目标，分清排序、重复检测和更严格 IoU 门槛造成的变化。 |

## 怎么做出下一步决定

- **定位数量和代价。** 按权重分别报告四组目标数量、分母、各阶段丢失数量及无法归因数；同时列出总体 AP、AP_small、每张原图前向次数和端到端毫秒。耗时另用关闭逐层记录的原入口测量，保持同机、预热、GPU 同步和计时边界一致。
- **选一个优先位置。** 若切片救回组集中在“整图阈值前定位差，放大后定位改善”，优先研究哪些局部值得放大。若整图已有同类高 IoU 候选且能追到具体抑制框，优先查去重。若差异来自相同三尺度候选的取舍，优先查尺度选择。每个判断附上反例，并检查第二份权重是否也出现相同现象。
- **完成标准。** 留下一条可复查的真实样本链、一份双权重分组计数，以及“优先查哪个位置、依据是什么、哪种解释仍成立”的结论。若两份权重指向不同环节，就分别记录条件。两份权重都用裁片训练过，推断推广到整图训练的模型需要另做配对。
