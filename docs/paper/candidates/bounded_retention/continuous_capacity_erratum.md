# 容量例参数勘误及后续验证义务

2026-11-05。检查`build_ideal_observation`的实际默认值发现：
`curved_3u_capacity_01`运行的是**精确理想tau=35/100**，而先前capacity_protocol
文字写了公开规则的0.35−1e−12。原receipt及源码快照保留，不回改使其看似匹配。
故该receipt是理想3U曲面的数值容量失败证据，不是该文字参数下的严格协议重放，
更不是实际公开来源/训练对象的验证。其体积28240.812573、界及111.35秒仍对应实际
执行的tau=.35；这已足以暴露通用矩形积分器的一个合法理想例局限，但不能冒称全部
公开参数已测。新采样验证须分别覆盖这个原理想例以及实际binary64(.35)减
binary64(1e−12)的公开阈值/容差理想实数差，并在receipt直接记载tau，避免再依赖默认值。
它不是生产SOURCE_OUTER的逐对象有效阈值；实际有效阈值还包含认证的导出算术预算。
