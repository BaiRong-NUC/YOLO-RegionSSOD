# 零训练成本入口：初始化进展监控修订

2026-11-06，先于第二次真实零训练诊断冻结。原容量合同不改。

`real_01`在train_loader_setup阶段被新诊断脚本监控120秒后结束。
当时没有显式batch模型前向、loss、反向或优化器步骤，不能认定为机制或点求解容量失败。
原因是入口将本来针对每次请求/loss的墙钟预算也施加到整个人工来源对象绑定初始化，
且没有上报初始化内部进展。原记录、源码快照、初始权重副本与进程身份全部保留。

修订仅增加初始化进展心跳：原BoundSourceFactory每完成5000个合法对象绑定就报告
一次真实进展。返回的观测与来源认证不改，不跳对象、不截短合法训练loader。
这不是训练时限、cell限额或loss限额的放宽。监控仍对无进展阶段采用120秒，
**进入每次loss/backward后不发送内部进展心跳，仍严格限时120秒**。
初始化的总耗时单独计入诊断准备成本，不冒充稳定训练batch成本。

源代码修订后重新执行全库pytest；通过后才在新的
`outputs/bounded_retention_point_review_20261106/real_02/`执行相同固定首16+16批次。
输出路径仅允许本合同root下全新real_NN直接子目录，旧real_01不写入。
不重新采样合成压力例，不恢复任何学生训练，不提高20000 cells、1e-5 gap、
K256、16384 proposals、256 bits或每次完整loss的120秒。
若真正loss失败/超时，按原合同停止并保存现场，不跳过该批继续挑选有利结果。
