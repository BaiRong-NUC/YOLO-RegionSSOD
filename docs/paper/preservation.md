## 只读核对

在仓库根目录、yolo环境：

```powershell
python scripts/preserve_paper1.py --audit
```

该命令验证两个ZIP哈希和归档内逐文件哈希，不依赖原件仍在原路径。
创建时已经额外比较原件；以后继续研究会合理改变日志/缓存，
此时可单独复核备份而不要求现工作目录与历史完全相同。
若确需检查原件一致性，可运行：

```powershell
python scripts/preserve_paper1.py --audit --compare-originals
```

`--create`已执行，重复默认命令会拒绝覆盖；将来新保存点需显式指定
`--directory outputs/paper1_preservation/<新的唯一目录>`。
原件始终不删除、不移动。未提供自动覆盖式恢复功能。
若需要恢复旧版本，先将归档解压至新的目录核对，再按具体任务引用；
不要在当前工作树执行破坏性重置。

## 历史审计回执的保存修复

原三个评估脚本的直接`--audit`会重写`independent_audit.json`时间戳。
后续尺度分析绑定了高精度诊断原回执的哈希，重复审计会导致这条来源链失配。
本轮首次复核暴露该问题；快照还显示，本轮开始时的18:56:14回执已经晚于
下游绑定的首次18:51:01回执，本轮直接重放又生成了19:42:12回执。
新旧版本均保留在`outputs/paper1_writeup_20261102/audit_receipt_recovery/`。

依据首次`audit_exit.json`完成秒和原序列化规则，还原首次回执字节，
其SHA256精确等于下游冻结manifest已有值
`361d6a35a85100adb522849ddd9bc4a7352118c542dc7fe10fe701fc143ed7b2`。
只有该逐字节匹配通过才允许恢复，不修改manifest预期值或放宽哈希验证。
数值、权重、原诊断结果和原ZIP快照均不改写；因此快照仍保存本轮开始时的18:56版本。
恢复后`--compare-originals`会报告此已记录差异，归档自身`--audit`仍应通过。

今后用独立入口重放：

```powershell
python scripts/audit_paper1_frozen.py --stage all
```

它复用原评估计算，仅将三种已知验收回执写入新时间戳目录；
拒绝其他通过共享写入函数发生的写操作，并核对历史回执前后哈希相同。
各阶段验证范围继承原实现，尺度分析仍只独立重放数值摘要、不含完整fold记录列表，
后者由产物哈希保护；这不是另一套独立指标实现。
