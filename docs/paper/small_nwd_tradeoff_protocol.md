# NWD召回与误检取舍：缓存离线诊断

2026-10-30。用户询问为何小目标召回提高但未通过继续线。本项在已知
5epoch的mAP和固定操作点recall之后登记，属于事后解释，不是独立确认。
原`small_nwd_protocol.md`的继续线、失败结果、C/mix/面积阈值均不修改。
不新增教师/学生推理或训练，不根据本项val结果生成伪标签或选择损失参数。

输入为完整P1和小框NWD的两组548原图预测、对应val960类别AP及原始val标签。
保存预测的conf下限0.25、NMS IoU0.7、max_det500保持原样。
匹配采用原recall的逐图类别一致/置信度递减贪心，全部GT尺寸联合匹配、
每个GT最多一次。small/medium/large按原图GT面积32²/96²分组。
误检定义为这个YOLO标签口径下所有未匹配预测，不能称为VisDrone官方误检。

固定输出：

1. conf为0.25/0.30/0.40/0.50/0.60/0.70/0.80/0.90，
   匹配IoU为0.50/0.75/0.90的总TP/FP、precision及分尺寸recall。
2. 每个IoU下，用P1的conf0.25和0.50产生两档全尺寸FP预算；
   NWD只在缓存conf≥0.25的所有实际分数阈值中，选不超过该预算的最宽前缀。
   同分预测必须整组接受/拒绝，不能拆分或插值出不可实现的操作点。
   阈值来自val GT，是描述性诊断，不作为部署阈值或继续训练的过线证据。
3. 重放已保存的10类AP50-95差值，均值必须恢复原mAP变化。
   现有AP没有逐IoU曲线，不能据严格IoU召回把AP损失归因为某一个原因。
